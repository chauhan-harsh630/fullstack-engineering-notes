# 🛡️ Cross-Site Request Forgery (CSRF) Prevention

## 📖 Overview

**Cross-Site Request Forgery (CSRF)** forces an authenticated end user to execute unwanted actions on a web application in which they are currently authenticated.

If your site relies solely on ambient browser cookies for authentication, a malicious site visited by the user can trigger an automatic hidden POST request to `yourbank.com/transfer` and the browser will automatically send `yourbank.com` cookies!

---

## 🛠 Mitigation Techniques

1. **`SameSite` Cookie Attribute**: Set `SameSite=Strict` or `SameSite=Lax` on all authentication cookies.
2. **Anti-CSRF Tokens (Synchronizer Token Pattern)**: Require a unique, unpredictable token generated by the server to be sent in request headers for state-changing HTTP requests (POST, PUT, DELETE).
3. **Custom Headers**: For SPA/REST APIs, requiring a custom header like `X-Requested-With` or `Authorization: Bearer <token>` naturally blocks standard HTML form CSRF submissions.

---

## 📌 Summary
* `SameSite=Strict` cookies + custom authorization headers effectively eliminate CSRF risks for modern REST APIs.
